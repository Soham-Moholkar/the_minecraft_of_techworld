# Deployment review boundary

Assets: operator token, tenant deployment scope, retained application data, host
credentials and cluster authority. The browser receives a typed projection of
fixed resource identities, numeric totals, findings and a manual teardown plan.

Threats: manifests can hide sidecars, public services, host mounts, inline secrets,
service-account authority, excessive replicas, missing probes, alternate namespace,
permissive network rules, unknown cluster-wide resources and retention changes.
Whole-object independent contract comparison rejects these and numeric/boolean
type substitutions. Unknown content is never echoed; resource names/messages are
drawn exclusively from the contract. File reads reject redirection and exceed no
256 KB; malformed content produces a redacted unavailable observation.

Owner/development/northstar guards run before reading source. There are no upload,
path, context, shell, apply or delete request inputs. BFF server credentials stay
private, redirects are rejected, responses bounded and no-store. Structured logs
and counters use fixed status values. Runtime review never invokes installed CLI.

Limits: a hostile OS administrator can change source and policy; this is an
operator trust boundary. Passing a chart contract cannot prove cluster admission,
CNI enforcement, image contents, filesystem permissions or cloud billing. Teardown
is text to review; context and labels must be independently verified before use.
Live local acceptance and release signing are required before broader authority.

Local IaC adds a second independent observation. Entire source configuration is
allowlisted before the operator CLI; only builtin terraform_data and validated
budget metadata enter a unique fixture. External providers/modules/data sources,
provisioners, backend credentials, arbitrary tfvars and inherited cloud keys are
excluded. Native apply/destroy is limited to that verified disposable builtin
state. The API has no executable tools. Only content-bound redacted receipts are
published; raw plans/state are potentially secret-bearing and never reach HTTP.
The plan policy rejects unknown/sensitive masks and alternate/deleting resources.
Operator filesystem tampering is a documented trust boundary, not a remote signature
claim. Actual cloud pricing, state locks/backups and destructive approval remain future.
